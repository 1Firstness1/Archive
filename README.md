# Архив документов — Информационная система

## Описание
Проект представляет собой модульную информационную систему учёта и выдачи архивных документов:
1. **Бэкенд (Spring Boot REST API + Docker)** — каталог `backend`. Отвечает за аутентификацию, регистрацию, управление сессиями и работу с PostgreSQL.
2. **Настольное JavaFX-приложение (КР №2)** — каталог `javafx-client`. Полнофункциональный настольный интерфейс с авторизацией, CRUD-операциями, фильтрацией, сортировкой, статистикой и экспортом данных в XLSX/CSV.
3. **Консольное приложение (КР №1)** — располагается в каталоге `src` (корень).

Система использует СУБД PostgreSQL для надёжного хранения данных и построена по многослойной архитектуре.

## Порядок и последовательность запуска системы

> **Важно**: Если запустить только JavaFX-клиент без предварительного запуска инфраструктуры, окно приложения откроется в автономном режиме, но операции авторизации и работы с данными будут заблокированы до подключения.  
> **Правильная последовательность запуска:**
> 1. Сначала **Docker и PostgreSQL + Backend**;
> 2. Проверка доступности REST API;
> 3. Запуск **JavaFX-приложения**.

### Шаг 1. Запуск инфраструктуры (Backend + PostgreSQL в Docker)

Перейдите в каталог `backend` и запустите сервисы:
```bash
cd backend
docker compose up -d
```

Docker поднимет:
- Контейнер базы данных `archive_postgres` на порту `5432` (с автоматической инициализацией таблиц из `sql/init.sql`).
- Контейнер бэкенда `archive_backend` на порту `8080`.

Для проверки статуса контейнеров:
```bash
docker compose ps
```

Для просмотра логов:
```bash
docker compose logs -f
```

---

### Шаг 2. Запуск настольного JavaFX-клиента (КР №2)

Перейдите в каталог `javafx-client` и запустите приложение через Maven:
```bash
cd javafx-client
mvn javafx:run
```

#### Авторизация в JavaFX-приложении:
- При запуске приложения открывается окно авторизации и регистрации.
- **Стартовые учетные данные** хранятся в файле `backend/.env`:
  - **Логин**: `admin`
  - **Пароль**: `admin123`
- При необходимости новый пользователь может зарегистрироваться через вкладку **«Регистрация»**.
- После успешного входа в верхнем меню доступна кнопка **«🔑 Сменить пароль»** для обновления своего пароля через REST API.
- Если контейнеры выключены, приложение показывает предупреждающий баннер и кнопку **«🔄 Проверить подключение»** для горячего подключения без перезапуска.

---

### Шаг 3. Запуск консольного приложения (КР №1)

Оставаясь в корневом каталоге проекта:
```bash
mvn compile exec:java -Dexec.mainClass="ru.mirea.archive.Main"
```

## Функциональность JavaFX-клиента
- **Авторизация и безопасность**: вход по логину/паролю, регистрация новых пользователей, смена пароля через Spring Boot REST API.
- **Автономный режим**: корректный запуск и оповещение пользователя при недоступности инфраструктуры.
- **Полный CRUD**: создание, просмотр, редактирование и удаление запросов на документы и пользователей.
- **Поиск, фильтрация и сортировка**: по статусу, приоритету, названию и ФИО.
- **Статистика**: графическое распределение запросов по категориям, статусам и приоритетам.
- **Экспорт данных**: выгрузка в форматы XLSX и CSV (с возможностью экспорта сразу обеих таблиц по очереди).

## КР №3: Полнофункциональный REST API и веб-интерфейс

В рамках курсовой работы №3 информационная система расширена современным защищённым REST API и SPA веб-интерфейсом на React:

### 1. Архитектура бэкенда и БД
- **Стек**: Java 21, Spring Boot 3.2.5, Spring Security, Spring Data JPA, Flyway, PostgreSQL, Hibernate Validator, Springdoc OpenAPI, Actuator, Apache Commons CSV.
- **Пакетная структура**: `controller`, `service`, `repository`, `domain`, `dto`, `security`, `filter`, `error`, `config`.
- **Flyway миграции** в `db/migration`:
  - `V1__init_schema.sql` — создание таблиц `users`, `document_requests`, `document_request_tags`, `document_notes`, `app_accounts`, `refresh_sessions`, `audit_logs`, индексов для поиска, внешних ключей и ограничений целостности.
  - `V2__seed_data.sql` — начальные данные заявителей, запросов документов, тегов, заметок и учётных записей.
- **Hibernate**: `ddl-auto: validate`, `open-in-view: false`.

### 2. Авторизация, сессии и безопасность
- Вход по логину и паролю, выдача короткоживущего **access JWT** и отдельного **refresh-токена** с серверной сессией (`refresh_sessions`).
- Ротация refresh-токенов при обновлении и отзыв сессии при выходе (`POST /api/auth/logout`).
- Пароли хранятся исключительно в виде **BCrypt**-хешей. Пароли исключены из всех DTO.
- Защита от брутфорса: блокировка учётной записи на 15 минут после 5 неудачных попыток входа (`LoginAttemptService`).
- Принудительная смена временного пароля (`mustChangePassword`) при первом входе после создания или сброса пароля администратором.
- Запрет входа для отключённых пользователей (`active = false`).
- 3 уровня доступа: **Читатель** (`ROLE_VIEWER`), **Редактор** (`ROLE_EDITOR`), **Администратор** (`ROLE_ADMIN`).
- Единый сквозной **Correlation ID** (`X-Correlation-ID`) в MDC и HTTP-заголовках.
- Единый JSON-формат ошибок (400, 401, 403, 404, 409) без утечки stack trace.

### 3. Основная сущность (`document_requests`) и справочник (`users`)
- **Основная сущность**: UUID (`uuid`), внешний номер (`requestNumber`), заявитель из справочника (`user_id`), название документа (`documentTitle`), описание (`description`), категория (`category`), статус (`status`), приоритет (`priority`), число страниц (`pageCount`), гриф секретности (`confidential`), вычисляемый показатель срока обработки (`estimatedDays`), теги (`tags`), признак архива (`archived`), поле `@Version` для оптимистичной блокировки.
- **Операции над сущностью**: список с пагинацией и сортировкой, карточка по UUID, создание, редактирование с проверкой версии (`409 Conflict`), архивация (`DELETE`), восстановление (`POST /restore`), окончательное удаление (`DELETE /permanent`, только ADMIN).
- **Поиск и фильтры**: полнотекстовый поиск, фильтры по справочнику, статусу, приоритету, грифу, архивности, тегам, вычисляемому показателю, числовому полю с операциями сравнения (`eq`, `gt`, `lt`, `gte`, `lte`).
- **Справочник заявителей (`/api/users`)**: просмотр, добавление, редактирование, включение и отключение (хранение отключённых в БД, право редактирования только у ADMIN).
- **Заметки (`/api/document-requests/{id}/notes`)**: история заметок, создание, редактирование, удаление, закрепление (`pin/unpin`), фиксация автора и времени.

### 4. Массовые операции, CSV и аналитика
- **Массовые операции (`POST /api/document-requests/bulk`)**: обработка по списку UUID (архивация, восстановление, смена статуса, добавление/удаление тега) с детализацией успешных и ошибочных записей.
- **Экспорт CSV (`GET /api/document-requests/export`)**: экспорт с учётом активных фильтров.
- **Двухэтапный импорт CSV**:
  1. `POST /api/document-requests/import/preview` — валидация строк, подсчёт корректных и ошибочных записей, список ошибок.
  2. `POST /api/document-requests/import/apply` — применение с выбором режима (`CREATE_ONLY` — только новые, `UPDATE_EXISTING` — обновление по номеру).
- **Аналитическая сводка (`GET /api/analytics/summary`)**: общее число, активные/архивные, секретные/открытые, средний объём страниц, группировки по статусу, категории, заявителю и вычисляемому показателю.
- **Журнал аудита (`GET /api/admin/audit`)**: события входа, изменений данных, массовых операций и импорта с Correlation ID (доступ только ADMIN).
